**Use Python 3.12 or later.** `pip` and `uv tool` install the published package.
These docs follow `main`; use a checkout for changes listed as
[unreleased](release_notes/HISTORY.md#unreleased).

## Requirements

| Requirement | Needed for |
|---|---|
| Git and [GitHub CLI](https://cli.github.com) (`gh`) | GitHub repository access, including when using `GITHUB_TOKEN` |
| Docker | Native pipelines that execute target code; local Harbor trials |
| Modal or Daytona credentials | Remote recipes, Tasksmith and quality-loop execution |
| Node.js 22.19+ and npm | Tasksmith's Pi/OpenCode author runtime |
| Model credentials | Bootstrap, authoring, review and solver stages that call a model |

PR-diff generation needs neither Docker nor a model key. Its **grading** does need
a correctness judge. Review-only quality runs call a model but do not need a worker.

## Install

```bash tab="pip"
pip install repo2rlenv
```

```bash tab="uv"
uv tool install repo2rlenv
```

For Harbor in the same environment:

```bash tab="pip"
pip install 'repo2rlenv[harbor]'
```

```bash tab="uv"
uv tool install --upgrade 'repo2rlenv[harbor]'
```

This exposes both `repo2rlenv` and `harbor`. The extra selects the Harbor version
supported by that Repo2RLEnv release; avoid upgrading the in-process runner independently.

### From a checkout

Use a checkout for Tasksmith and remote recipes so the controller and uploaded
runtime wheel come from the same source:

```bash
git clone https://github.com/huggingface/Repo2RLEnv
cd Repo2RLEnv
uv sync --frozen --extra tasksmith --extra daytona --extra harbor
uv build --wheel
uv run repo2rlenv --version
```

Choose the extras below; replace `daytona` with `modal` when needed. Run checkout
commands as `uv run repo2rlenv …`. The wheel is written under `dist/`; pass its
actual path to `--runtime-wheel` or `execution.runtime_wheel`.

**Rebuild after changing or updating the source.** Remote workflows compare the
wheel's package contents with the installed controller and reject a stale wheel.
[Remote execution](guides/remote-execution.mdx) walks through a complete run.

### Tasksmith runtime

After installing the `tasksmith` extra, install the pinned coding-agent runtime:

```bash
uv run repo2rlenv tasksmith install-runtime
```

Repeat this after an update changes the runtime lockfile.

## Extras

| Extra | Enables |
|---|---|
| `harbor` | Harbor models and trial execution for recipes, review and release workflows |
| `modal` | Modal workers and supported native GPU trials |
| `daytona` | Daytona workers |
| `tasksmith` | LangGraph orchestration and checkpoint storage |
| `mutation` | SWE-smith's Python source-mutation support |
| `mutants` | Go, Rust and JavaScript/TypeScript assertion controls through tree-sitter; Python controls use the standard library |

The base package includes model calls through LiteLLM and Hub transfers through
`huggingface-hub`. See [pyproject.toml](https://github.com/huggingface/Repo2RLEnv/blob/main/pyproject.toml)
for dependency bounds and `uv.lock` for the exact checkout environment.

### Tested source compatibility

As of **November 24, 2026**, `main` pins Harbor **0.26.0**, Daytona **0.231.0** and
Modal **1.6.4**. Its lock selects LiteLLM **1.110.2**, OpenAI **3.51.0** and Hub
**2.4.0**. These are the current source contracts, not the original 0.9.6 release's
lock. The [unreleased notes](release_notes/HISTORY.md#unreleased) describe the changes.

Use the repository lock for remote adapters. A provider SDK's next major version
is not automatically compatible with the controller or Harbor integration.

### Filelock security override

Current source and the 0.9.6 release require patched `filelock>=4.2.1,<5` with a
compatible stable LiteLLM release. **No filelock override is needed.** The workaround
for older 0.9.5 installations is historical; see the
[0.9.5 release notes](release_notes/HISTORY.md#v095-verifier-hardening-and-stable-dependency-updates).
Prefer a fresh, supported installation when upgrading.

## Credentials

| Service | Set up | Used by |
|---|---|---|
| GitHub | `gh auth login` or `GITHUB_TOKEN` | PR mining and Tasksmith intake |
| GitLab | `GITLAB_TOKEN` | Supported native GitLab sources |
| Model provider | `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` or the configured provider's variable | Authoring, review and model-backed bootstrap |
| Hugging Face | `hf auth login` or `HF_TOKEN` | Hub downloads and publication; writes need permission |
| Modal | `uv run modal setup`, or `MODAL_TOKEN_ID` and `MODAL_TOKEN_SECRET` | Modal workers and trials |
| Daytona | `DAYTONA_API_KEY` | Daytona workers and trials |
| Container registry | GHCR or Docker Hub credentials | Distribution of native bootstrap images |

Model selection is explicit through `--llm provider/model` or workflow options.
`--llm-key-env` selects a credential variable and `--llm-endpoint` supports a
compatible endpoint where that command accepts it. Tasksmith authoring currently
uses Anthropic models; its quality stages can use OpenAI or Anthropic.

Harbor's agent and verifier receive credentials separately through `--ae` and
`--ve`. See [run with Harbor](guides/run-with-harbor.mdx#pass-api-keys),
[authentication](reference/AUTH.md) and [registry setup](reference/REGISTRY_AUTH.md).

### Using a `.env` file

Repo2RLEnv searches the current directory and its parents for `.env`, without
overriding existing shell variables. See [environment configuration](reference/ENV.md#env-files)
and `.env.example`. Harbor is a separate CLI: pass its needed variables explicitly.

## Platform support

Use Linux or macOS; WSL is the Windows route for full controller workflows.
Native Windows CI covers CLI startup, discovery, emission and static checks.
It does not establish full remote-controller portability. Choosing a cloud worker
does not remove the controller's host requirements.

## Verify your install

```bash
repo2rlenv --version
repo2rlenv pipelines list
repo2rlenv pipelines describe repo_mutate --recipe swe_smith
```

These commands do not launch workers or model calls. Continue with the
[quickstart](quickstart.mdx), [Tasksmith](pipelines/tasksmith.md#run-one-pr) or
[remote recipe setup](guides/remote-execution.mdx).
