title: "Quickstart"
description: "Generate PR-diff tasks, check their files, then run their reference and baseline controls."
---

This walkthrough uses `pr_diff` to turn merged PRs from `pallets/click` into
Harbor tasks. **Generation needs Python 3.12+, Git and the GitHub CLI.** Executing
the tasks later needs Docker and a model key for the correctness judge.

For test-based rewards, start with [pr_runtime](pipelines/pr_runtime.md) or
[Tasksmith](pipelines/tasksmith.md). The examples below use patch similarity.

<Steps>
<Step>

### Install Repo2RLEnv

```bash tab="pip"
pip install repo2rlenv
```

```bash tab="uv"
uv tool install repo2rlenv
```

```bash
gh auth login
```

You can use `GITHUB_TOKEN` instead of interactive login, but `gh` must still be
installed. [Installation](installation.mdx) covers extras and checkout installs.

</Step>
<Step>

### Generate tasks from three PRs

```bash
repo2rlenv generate --repo pallets/click --pipeline pr_diff \
  --pipeline-opt limit=3 --out ./tasks
```

`limit=3` means **three candidates**, not three guaranteed exports. Filters remove
changes such as docs-only patches, reverts and oversized diffs. A summary might be:

```text
candidates  3
emitted     1
skipped     2 ({'too_many_files': 2})
```

This is illustrative; the repository's latest PRs determine your result. If no task
is emitted, the command exits 1. Increase `limit` or try a different repository.

</Step>
<Step>

### Look at what you made

```files
tasks/
└── pallets__click-<pr>/
    ├── task.toml           # configuration, source PR and evaluation label
    ├── instruction.md      # the learner's request
    ├── environment/       # checkout at the PR's base commit
    ├── solution/          # reference patch and solve.sh
    └── tests/             # private patch capture, scorer and reference diff
```

The learner edits the starting checkout. During grading, the verifier captures
that change and compares it with the reference patch, using deterministic
similarity components and a correctness judge. Read the
[task layout](concepts/tasks.mdx) and [PR-diff reward](pipelines/pr_diff.md#multi-component-reward)
for the full contract.

</Step>
<Step>

### Validate the tasks

```bash
repo2rlenv validate ./tasks --oracle
```

This checks the native task format, required files and oracle assets. **It does
not build the image, run the reference or establish task quality.**

</Step>
<Step>

### Run the tasks with Harbor

Start Docker and install the Harbor integration:

```bash tab="pip"
pip install 'repo2rlenv[harbor]'
```

```bash tab="uv"
uv tool install --upgrade 'repo2rlenv[harbor]'
```

Set `ANTHROPIC_API_KEY` in your shell, then run the reference (`oracle`) and the
untouched baseline (`nop`). These controls incur judge calls.

```bash
harbor run -p ./tasks -a oracle --env docker \
  --ve ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY"
harbor run -p ./tasks -a nop --env docker \
  --ve ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY"
```

The reference should receive a high score and the baseline should score zero.
Unlike binary test tasks, the PR-diff reference score includes a model judgment.
If the judge is unavailable, the trial is **ungraded** and has no reward file;
Harbor reports `VERIFIER_FAILED`. Diagnose that separately from a scored failure.

Now try a solver:

```bash
harbor run -p ./tasks -a claude-code -m anthropic/claude-sonnet-4-6 \
  --ak max_budget_usd=2.00 \
  --ae ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" \
  --ve ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" --env docker
```

`--ae` supplies the agent key; `--ve` supplies the judge key. The $2 setting caps
the Claude Code agent's spend per task, **not** judge calls or sandbox costs.
Results and traces go to `jobs/`; use `harbor view jobs` to inspect them.
[Run with Harbor](guides/run-with-harbor.mdx) covers other agents and providers.

</Step>
<Step>

### Push to the Hub (optional)

Authenticate, then replace `YOUR_NAME` with your Hub username or organization:

```bash
hf auth login
repo2rlenv push ./tasks YOUR_NAME/click-pr-diff --private
```

This publishes task files, a dataset card, a manifest and a Harbor registry. It
adds no quality guarantee. See [publishing](guides/publishing.mdx) for public
releases and container images.

</Step>
</Steps>
